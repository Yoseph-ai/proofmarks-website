# Security Audit Report

This report summarizes security and logic issues discovered in the current workspace. No hard-coded Hedera credentials were found in committed source files, and `.env.example` contains placeholders only.

| Severity | Location | Description | Remediation |
|---|---|---|---|
| High | `src/lib/hederaService.js:94` | Duplicate detection is performed by scanning the Mirror Node via `verifyHash()` before submitting a new `TopicMessageSubmitTransaction`. This is not atomic and can allow concurrent requests to submit the same hash twice, leading to duplicate ledger entries and inconsistent client behavior. | Remove the pre-submit duplicate scan or replace it with a serialized deduplication mechanism / external store. On Hedera, avoid racing read-before-write checks against the public mirror node. |
| Medium | `src/lib/hederaService.js:163-178` | `verifyHash()` performs an unbounded full scan of topic messages and follows `data.links.next` without a page limit. This can cause slow responses, unbounded resource use, and potential DoS if the topic grows large or if the Mirror Node returns many pages. | Add a maximum page/record limit and normalize `next` URLs. Example: `let pages = 0; const maxPages = 20; while (nextUrl && pages < maxPages) { ... nextUrl = data.links?.next ? new URL(data.links.next, mirrorNodeUrl).toString() : null; pages++; }` |
| Medium | `src/app/api/certificate/[certificateId]/route.js:10-22` | `certificateId` is parsed with `substring()` and used directly in a Mirror Node request URL. Malformed or malicious `certificateId` values can cause invalid fetch targets or unexpected behavior, and the route does not enforce strict certificate ID syntax. | Validate `certificateId` strictly before use, e.g. `const match = certificateId.match(/^\d+\.\d+(?:\.\d+)?@\d+$/); if (!match) return Response.json({ error: 'Invalid certificate ID' }, { status: 400 });` |
| Medium | `src/app/verify/[certificateId]/page.tsx:17` | The client page interpolates `certificateId` directly into `/api/certificate/${certificateId}` without URL encoding. Special characters in the route parameter may break requests or lead to invalid path handling. | Use `encodeURIComponent(certificateId)` or normalize the route parameter before calling the API. |
| Medium | `src/app/api/timestamp/route.js:6` and `src/app/api/verify/route.js:6` | The timestamp and verify APIs are public and unauthenticated. Any client can submit hashes, trigger Hedera lookups, or enumerate certificate data, which allows abuse and spam of the backing Hedera service. | Add authentication and/or rate limiting to API endpoints, such as API keys, bearer tokens, or request throttling based on environment configuration. |
| Low | `src/app/timestamp/page.tsx:75-89` | The front-end certificate worker payload uses `data.sequence || 'N/A'`, but the server response includes `sequenceNumber`, not `sequence`. This mismatch can cause certificate PDF generation to display an invalid sequence value. | Align API response property names with client expectations or update the client to use `data.sequenceNumber` consistently. |
| Low | `src/app/api/certificate/[certificateId]/route.js:20-23` | The certificate API fetch URL is built using user-supplied `topicId` and `sequenceNumber` without sanitization, and the Mirror Node response is assumed to contain `msg.message`. Invalid responses may produce runtime failures. | Add input sanitization and return a safe error when Mirror Node payloads are missing expected fields. Example: `if (!msg?.message) return Response.json({ error: 'Malformed certificate record' }, { status: 502 });` |

## Notes
- No committed `.env` file or hardcoded Hedera private key was found.
- `.env.example` contains placeholder values only.
- The application currently lacks any authorization layer for server APIs. If the service is intended for anything beyond an open public demo, authentication should be added.
